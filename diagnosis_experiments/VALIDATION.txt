CohereKV diagnosis_experiments validation checklist

Design invariants
-----------------
1. Original diagnosis uses the production build_merge_plan implementation.
2. Original routing uses the released C/R/D/Gamma <= Delta rule.
3. Original filtering uses the released conflict graph + degree-priority Parallel MIS.
4. Delta is frozen from first-compression S_ref on the original trajectory.
5. Compatible Merge-All uses the same original routes and only disables source-source filtering.
6. Fresh-Certificate is a same-state diagnostic shadow: R=D=0 only for plan construction.
7. Refreshed-Scale is a same-state diagnostic shadow: accumulated R,D are preserved but S_ref/Delta is recomputed.
8. Only Original CohereKV advances the repeated-compression trajectory.
9. Probe-query errors are post-hoc diagnostics and never affect routing, graph construction, or MIS.
10. Figures explicitly state compared systems/quantities in titles, axes, and legends.

Packaging checks
----------------
- Python syntax check for both scripts.
- bash -n check for run_diagnosis.sh.
- Import smoke check for production mymethod_common planner.
- Synthetic planner check: first-round R=D=0 and fresh-certificate shadow produce identical plans.
- Synthetic multi-round state-update check: count mass equals surviving original-token membership.
- Plot smoke test produces every diagnosis figure from synthetic CSVs.
- Existing repository files outside diagnosis_experiments remain byte-for-byte unchanged.
